# Task 08 — HTTP API Implementation Plan

**Goal:** Expor os contratos do §9 pelo NestJS sem duplicar ProcessWagerUseCase, com abertura atômica e reconciliação exata.

**Architecture:** Controllers delegam a casos de uso; validação e serialização ficam nos adapters. UnitOfWork oferece snapshot read-only REPEATABLE READ. Persistência existente e fronteiras permanecem preservadas.

**Tech Stack:** Bun 1.4.4, NestJS 11, TypeScript strict, MikroORM 7, PostgreSQL 18.3.

**Spec:** [challenge.md §9](../../challenge.md), [Financial](../../domain/financial.md), [Wagering](../../domain/wagering.md) e escopo Task 08 fornecido pelo usuário.

## Pontos de revisão

WalletId divergente inclusive em replay não pode executar outra wallet; igualdade de timestamps não determina ordem financeira; cursor não deve perder microssegundos PostgreSQL; SQLSTATE genérico não identifica duplicata de wallet; liveness deve continuar respondendo durante falha de banco.

Ruling: a rota de readiness exigida no §9 verifica PostgreSQL e retorna 503 enquanto SQS estiver ausente. Readiness completo depende da etapa de mensageria; não anunciar saúde SQS fictícia. Autenticação omitida com guard no-op explícito para futura integração com IdP, sem autenticação customizada.
